The [dabba](https://github.com/spice-labs-inc/dabba) platform, as gitops. A
[FluxInstance](https://github.com/controlplaneio-fluxcd/flux-operator) (set up by the
[`flux-operator`](https://github.com/spice-labs-inc/dabba-modules/tree/main/modules/flux-operator)
module) syncs `clusters/<name>/`, which declares the Flux Kustomizations that build the cluster:

```
crds/overlays/<overlay>                 # operators that bring CRDs (reconciled first, wait=true)
platform/overlays/<overlay>             # platform core (gateway, issuers, secret stores)
use-cases/<use_case>/overlays/<overlay> # what this cluster is for
```

The Kustomizations live here in `clusters/`, not in the OpenTofu — the cluster is
self-describing. OpenTofu only points the FluxInstance at a `clusters/<name>/` path and stamps
a `cluster-vars` ConfigMap; everything else is reconciled from this repo.

## Layout

- `clusters/local/` — the per-cluster Flux Kustomizations (the sync target). `kustomization.yml`
  here is **generated by dabba** from `dabba.yaml` — it's the managed selection of which
  Kustomizations are active (e.g. `observability.yaml` is added when observability is enabled).
- `crds/base/` — cert-manager, envoy-gateway, external-secrets-operator HelmReleases
- `platform/base/` — the cloud-free core: GatewayClass + EnvoyProxy, `cluster-css`
  ClusterSecretStore, random-key ClusterGenerator
- `platform/components/` — opt-in pieces overlays compose:
  - `selfsigned-issuer` — `dabba-ca` ClusterIssuer for local TLS
  - `openbao-dev` — in-cluster dev-mode OpenBao + `openbao` store (local only)
- `platform/overlays/local` — base + both components + NodePort envoy (pairs with the kind
  module's host port mapping)
- `use-cases/demo` — podinfo behind the gateway, its banner delivered from OpenBao via ExternalSecret
- `use-cases/observability` — Vector + OpenObserve + an OTel collector (opt-in)

## Substitution variables

Read from the `cluster-vars` ConfigMap via `postBuild.substituteFrom`:

| Variable | Meaning |
|----------|---------|
| `${domain}` | base domain (`localtest.me` locally) |
| `${cluster_issuer}` | cert-manager ClusterIssuer for gateway certs (`dabba-ca` locally) |
| `${openbao_root_token}` | per-env OpenBao dev-mode root token (generated by the CLI; used by the `openbao-dev` component) |

`${environment}` and `${cluster_name}` are also stamped into `cluster-vars` for overlay use.

Cloud overlays (ACME issuers, external-dns, external OpenBao, LB gateways) are added as sibling
components/overlays under a new `clusters/<name>/` — the base stays cloud-free.
